# 个性化记忆与跨来源项目索引

在每周调研、旧项目复查或更新反馈时读取。状态是可纠正的工作记录，不是用户的完整画像，也不修改宿主自身的 memories。

## 先读后写与文件契约

先确定当前状态根（显式覆盖优先，默认见 SKILL.md），解析真实路径。写入只能位于该根；若子目录是指向根外的链接，不写入。根不存在时按当前任务创建。不得把丢失的项目根当作状态目录。

使用以下小型文件，不复制原始聊天和整个项目：
- `profile.json`：`schema_version`、`updated_at`、`settings`、`preferences`、`exclusions`。偏好条目保存 id、简短内容、kind（explicit / inferred）、source、verified_at；推测不可改成用户原话。
- `projects.json`：版本、更新时间、`sources`、`projects`。来源记录本次检查结果和覆盖范围。项目保存稳定 id、名称、来源定位、已确认根或仓库 URL、摘要、证据、状态、最近检查/复查时间。未读内容的 summary 为 null，不能用名称猜用途。
- `history.jsonl`：每行一个推荐或用户反馈事件。推荐记录 event_id、run_id、item_id、kind、fingerprint、title、project_ids、source_urls、novelty、created_at、report；反馈记录目标 run_id/item_id、明确选择/拒绝及理由。不把沉默写成接受。
- `reports/<日期>-<唯一后缀>.md`：本次报告。附覆盖范围、时间范围、来源证据、结论、未验证事项；已有文件不覆盖。

首次初始化只写已确认偏好，项目和历史可以为空。UTF-8 编码，日期使用带时区的 ISO 8601；本用户默认 Asia/Shanghai。每次运行生成唯一 run_id，推荐 ID 在报告中稳定，如 N01、O01。来源可以是文件路径、线程 ID 或直达 URL，不需要保存原始正文。

写入由主 Agent 串行完成。写前重读最新版本，基于稳定 ID 合并，不用旧快照覆盖新记录；用同目录临时文件校验 JSON 后替换。报告成功落盘后再追加对应推荐历史；写入中断时先检查 event_id、run_id 和文件是否已存在再恢复，不能重复追加。发现其他运行正在写同一文件，串行等待或保存当前报告并明确说明索引未更新，不抢写。

## 收集与增量更新

按当前工具注册表选入口，工具名仅供发现，不保证任意宿主都有：
- Codex app 的 `list_projects` 提供项目元信息；`list_threads` 提供有限近期/置顶聊天，`read_thread` 按需读相关内容。尊重工具返回的分页和参数上限。列举了项目不等于读过项目或其全部聊天。
- ChatGPT 云端项目目录、可读聊天与“ChatGPT 全局记忆”是三种不同能力；不声称拥有未提供的全局记忆接口。按实际覆盖记录，不绕过接口限制读取内部数据库。
- 聊天读取先限定少量轮次和正文长度；即使工具限长，返回中仍可能含很长的历史命令参数。在工具编排中只提取相关用户正文、最终答复和元信息，过滤工具调用与推理条目后再输出或写摘要，不转储整份返回。
- 连接器可能返回带临时授权参数的下载 URL；仅保留规范仓库/文件地址，不保存或展示签名查询参数、令牌及认证元信息。
- GitHub 优先使用连接器列仓库和读 README/必要入口，按 API 返回翻页。当前授权可访问不等于所有仓库都是用户亲自维护，区分拥有、参与和仅可见。
- 云文档只读与已知项目直接关联的文档；先检查连接和访问。未连接则记录缺口，不要求用户为本次结果临时配置，也不自动申请授权。
- 本地只检查宿主列出的项目根、用户指定路径和已索引路径。用 rg --files 或有限层级目录检查识别 README、AGENTS、manifest、Git 根；默认先两层，证据指向更深根时再定向读取。跳过依赖、构建、缓存、生成文件、认证和秘密材料。

初次列元信息、按相关性抽样；后续只更新发生变化或较久未复查的项目。每轮旧项目候选优先考虑明确待办/失败线索、最近活动和久未复查的有价值项目；避免每周只检查同一批。未读、未连接、失效、排除与已复查分别标注。

根目录消失先标 missing，不断言项目已被删除；仅按现有索引、已知项目根或用户提供的信息找新位置。目录内含独立子项目时建立独立记录与父级关系，不能把父工作区误当仓库。

跨来源合并首先使用核实的仓库 URL（剥除凭据、末尾 .git 与斜杠），其次使用 host + 真实规范目录。Windows 路径按不区分大小写比较，远端按实际文件系统规则；工作树保留各自位置。仅同名不合并，ChatGPT 项目与本地同名也不自动认定同一项目。保留来源别名，记录合并证据。

## 偏好、纠错、遗忘

- 当前用户明确说明 > 已有明确偏好 > 当前项目事实 > 旧摘要/推测。来源冲突保留必要的不确定性，不取热闹项目名替代用户目标。
- 学习、竞赛、研究、客户或团队项目只证明相关工作经历；不得自动归因用户身份、专业、教育阶段或人生计划。
- 稳定偏好有当前用户明确表述才写 explicit；行为推测标 inferred、附依据，只用于柔性排序，可被新证据替代。
- “少推荐”调整频率，不等于禁止；“别推荐”建立推荐排除；“不记住/忘记”清除本技能状态中对应事实和派生推测。
- 对遗忘要求，清理本状态目录中的 profile、projects、history、reports 及其临时副本；保留最小化的抑制规则或来源 ID，防止再次导入，不保留被遗忘的原话、细节或其哈希。若明确要求连排除标记也删除，则删除并说明今后无法自动阻止重读。
- 排除项可用 source ID、project ID、抽象类别或用户允许保留的主题；读取新资料前匹配。相关项目仍可在用户当前明确请求下临时处理，但不因此重新保存被排除的个人事实。
- 不改其他技能或宿主记忆，不声称已删除 ChatGPT 服务器、备份或原始聊天。旧聊天中的助手自称“已记住/已删除”不是已验证状态。

公开查询只使用抽象功能或技术主题，不携带私有仓库名、代码、个人材料或客户信息。未知隐私内容不写入公开报告。个人状态始终留在本地，除非用户另行要求分享。

## 去重与反馈

用“目标用户/对象 + 核心问题 + 主要能力”形成可读的语义 fingerprint，再人工比较历史近义项；换标题、换模型或换界面不算新点子。关联项目 id 与来源 URL 辅助去重，不仅比较链接。

重复调用只保留有意义的差异；新证据、新资源条件、新实现路径或用户重新关注，才可再推荐，novelty 标 revisit 并写明变化。明确排除的方向不因新热点绕过排除。反馈只影响用户指向的条目；模糊“这个”先利用当前上下文，否则澄清。未修改状态和报告时不能声称已经记住反馈。
